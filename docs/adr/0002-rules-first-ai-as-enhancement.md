# 判定以本地规则为底，AI 只做增强，且绝不成为单点故障

契合度判定、伤害计算、星级评价全部由**本地规则**依据素材标签与槽位声明算出；大模型只负责在规则结论之上补一段更像人话的点评与改写方向。AI 调用失败、超时、没配 Key、没网时，除了少一段点评，产品的每一个环节照常工作。

## 为什么

- **孩子点了「提交」就必须立刻得到反馈。** 因为欠费、限流、超时或家里断网而拿不到判定，会直接中断核心循环；对一个独立使用的小学生来说，中断就是关掉网页。
- **规则与 AI 互为质检。** 两者结论不一致时，往往说明某条素材的标签打错了。这是免费的内容质量信号，实测中就是这样抓到了「带『她』的句子挂了中性标签『同学』，导致写男生的题目把它判为完全契合」这个缺陷。
- **AI 对小学生作文的绝对评分不可靠**，但对「这句话适不适合放这个位置」这种单点分类判断相当可靠。因此把分数交给规则，把措辞交给 AI。

## 部署形态与已知风险

前端为纯静态文件，API Key 由使用者自己填在设置页、只存 localStorage，不进任何项目文件、不进档案导出。由此带来一个**尚未实测确认**的风险：

- **语音识别走 WebSocket**，浏览器对 WSS 不做 CORS 预检，静态页面直连很可能可行；但浏览器无法为 WebSocket 设置 `Authorization` 头，只能用子协议或 query 传递凭据，两种方式百炼是否都支持未经证实，代码里两种都试。
- **LLM 点评走 HTTPS**，很可能被 CORS 拦截，因为百炼未公开声明允许浏览器跨域。

因此设置页内置了「连通性自检」，由使用者用自己的 Key 实测两条链路并给出结论。若 LLM 直连不通，唯一的补救是加一层薄代理（Cloudflare Worker 之类）——那会牺牲「双击即用」，所以在自检给出结果之前不做。

## 相关取舍

- **背诵验收保留离线路径**（拖块重排 + 挖空填字）。语音验收依赖 Key、麦克风与网络，三者任一缺失都会让「攒技能」停摆，所以离线验收不是冗余功能，而是可用性保险。
- **语音识别失败时给孩子申诉按钮**（「我背对了，是它听错了」）。宁可技能库略有水分，也不让孩子因为机器听错而失去对系统的信任；注水会在挑战环节自然暴露。
